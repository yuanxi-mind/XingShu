# 有角色、有颜色，但仍能安心工作的界面

2026-11-17 查看。适用于用户明确要求可爱角色、宠物或更鲜明配色时；不是所有产品都该变成二次元。星枢的设计案例：用 Q 版 Agent 帮助区分身份，同时保证中文排版和聊天空间。

## 真正看过的参考

### E01 · Duolingo 的角色、颜色和正文分层

- 官方文章：https://blog.duolingo.com/core-tabs-redesign/
- 文章标题：Elevating craft: How we refreshed our core tabs。发布 2026-02-04；页面修改时间 2026-11-05 不等于新设计发布日期。
- 实际查看：文章正文，以及 `Punchy`、`Soft` 两组设计探索图。它们是探索稿，不是最终上线稿。图片路径带 2026/01，不用路径冒充发布日期。
- 可见决定 → 效果：顶区的粉、蓝、橙与角色对应，下方长内容仍以浅表面和稳定排列承载 → 有明显个性，同时保留阅读区域。
- 迁移：给身份和区域分配颜色；正文先保证可读。统一画风和排版，允许不同身份有不同颜色。
- 边界：手机的大型插画页头不直接搬进桌面聊天；文章也明确讨论了每页放插画会浪费空间、却未必传达信息的问题。

### E02 · GitHub Octodex 的同一角色家族

- 官方画廊：https://octodex.github.com/
- 实际查看：官方画廊页面与 `partymartytocat.png` 完整插画。不是聊天界面参考，未宣称它是近期新设计。
- 可见决定 → 效果：共同的脸型与身体轮廓，配不同服装、道具、姿态 → 能看出同属一家，也能区分成员。
- 迁移：Agent 角色统一比例、线条和头像容器；用剪影、发色、配件建立区别。不要只把同一个小方块换五种颜色。
- 边界：只学角色系统，不把 Octocat 美术资产直接用作我们的品牌或 Agent 头像。

## 由本轮失败与试排得到的规则

以下是设计判断，不是来源原文或用户实验结论。

1. **先让人想亲近，再让功能退后。** 角色有明确落点：身份头像、空状态或一个角落伙伴。聊天区不能到处是漂浮宠物。
2. **角色与正文使用不同尺度。** 侧栏和发言头像可用脸部近景；全身用于更大的展示空间。实际看正常尺寸、深浅底和多人列表，不只看素材大图。
3. **颜色有职责。** 身份色稳定用于头像底、名字、小标签；主行动用一套强调色；成功、失败、等待保留状态含义，且配文字。身份颜色不表示业务角色或能力排名。
4. **装饰状态与真实状态分开。** 装饰宠物不能暗示模型正在执行；思考、等待批准、失败的动作必须来自真实运行事件。动效可关，减少动态效果时不依赖动画传递消息。
5. **不给用户的照片让位。** 默认角色只填补未设置头像的情况；用户自己的头像、完整背景图与现有主题继续优先。
6. **有性格也要有密度。** 列表底部的宠物不能把主要成员推到多层滚动后；窄窗口收起装饰。正文可保持安静，明暗主题不必都用灰。
7. **先看成品，再下判断。** 同样内容、同样窗口做最多两种方向。把图给用户看；不要拿通过类型检查或引用名牌当作审美验收。
