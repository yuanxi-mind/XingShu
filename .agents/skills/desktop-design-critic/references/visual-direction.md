# 从参考到成品的视觉设计方法

用于较大视觉改造或“整个界面都不好看”的请求。局部问题只取相关部分。来源标号 B01–B07 对应 [真实产品研究](visual-studies.md)，以下操作方法是本 skill 的综合建议，不冒充来源原文或实验结论。

## 1. 先建立可用的参考

挑选与当前任务匹配的少量参考；通常同类任务、复杂工具、不同表现力方向各有一个就有帮助。现有参考过时、没有实际屏幕或与用户口味不符时，再找新的。没有客观通用的“最好看 App”榜单。

每个有效参考记录：`页面/状态 | 来源与日期 | 截图 | 看得见的设计决定 | 产生的效果 | 可迁移规则 | 不适合照搬的部分`。

先确认图里哪些是 App，哪些是浏览器边框、桌面壁纸、宣传标题和展示背景。不要从营销页面学来巨大标题和空白，再塞进高密度工作台。不要靠未看到的动画、截图外区域或登录后流程支撑结论。

## 2. 定一个完整方向

用几句话定下这些选择，避免只写“极简高级、科技感”：

- **内容焦点**：用户第一眼该读哪一块，下一步该操作哪里。
- **构图**：固定和临时区域、空间比例的理由、宽度变化时怎样收放；正文与表格可采用不同宽度。
- **密度**：哪些地方需要扫读，哪些需要沉浸阅读；不能靠全局缩字解决拥挤。
- **字体**：中文主字体、可用字重、标题/正文/说明/数值/代码的角色。
- **色彩**：基础表面、内容表面、浮层、正文、辅助字、强调和语义状态的职责。
- **形状和深度**：圆角家族、结构线、阴影、选中态；嵌套元素的弧度应相容。
- **识别性**：一个有意图的视觉特征，例如头像语言、细致选中态、内容封面或状态动效。不要求一定添加装饰。

选择一个主视觉语言。其他产品只能提供经过翻译的原则，不能把多个产品的组件原样拼贴。用户明确指定复刻对象时，先对齐指定基准，不擅自加入另一套风格。

## 3. 在三个尺度上比较

### 整体：缩小以后还成立吗

把完整界面缩到约四分之一观看，再恢复正常大小。缩图只是辅助检查，不是科学的注意力测试。

- 第一眼是否落在主要内容？顶栏、侧栏、横幅、头像、按钮是否同时过亮、过大？
- 大块明暗和留白是否服务内容？空白是阅读余量、分组关系，还是无意义的外边距？
- 水平与垂直分区是否清楚？是否出现重复导航、双重标题、层层框套框？
- 除了参考产品的颜色，还有哪些构图关系真正被学到了？

参考：B01 的视觉权重、B04 的画布、B05 的聊天分区。不要先调小图标，试图掩盖整个构图失衡。

### 区域：同类元素像同一家人吗

- 同级标题、列表行、按钮和编辑器是否采用相同的间距与层级？
- 表面层次是否有明确职责？可以用背景差异、分组空白或线条，但不要每次同时用满。
- 内容密度是否与用途匹配？会话列表需要扫读；长消息、代码和论文需要舒适阅读。
- 选中、悬停、键盘焦点、未读、错误是否可区分？不能全用同一种亮色边框。
- 细边框、头像尺寸、图标线条粗细与控件高度是否互相协调？

参考：B02 的行结构、B03 的内容预览、B06 的对齐。统一不是把所有元素做成相同尺寸，而是让同一职责的元素保持一致。

### 细节：在原始像素下检查

- 中文和数字基线、图标的视觉中心、按钮文字与输入文字是否协调？
- 字体是否真的加载？是否出现混乱回退、假粗体、不同脚本字重不均？
- 分隔线、圆角、内外边距、阴影边缘是否稳定？是否有一像素错位、截断或挤压？
- 动效首尾是否跳位？流式内容是否导致整个页面反复晃动？

光学对齐可有小幅补偿，但应先确认布局原因，避免为单个截图堆叠例外。

## 4. 中文排版是本项目要求

本项目默认全中文文案和支持中文的界面字体；以后用户变更要求时更新设计简报。英文参考不授权输出一套英文页面。

- 导航、按钮、设置、权限、加载、空状态、出错和恢复提示都要中文；如“新建智能体”“中转站”“正在保存”。产品名、模型 ID、文件路径、代码和原始错误中的必要技术值保留原样。
- Windows 原型可优先使用本机验证可用的 **微软雅黑 UI / 微软雅黑**；需要另一种气质时，可考虑有合法可用文件的 **思源黑体 / Noto Sans SC**。不要只指定 Inter 或 Geist，让中文随机落到另一个字体。更换字体前检查可用性和授权，不为 skill 研究安装或下载字体。
- 字体文件存在不等于该 App 已使用该字体；在目标平台检查实际渲染和回退。
- 为主要字体指定可用回退；中文、标点、数字、英文模型名一起试排。尽量少用不同字体和字重，避免中文虚假加粗。
- 字号和行距按角色选择。在普通桌面缩放下，可把 14–16 CSS px 正文、12–13 px 次级信息作为**初始试排值**，再用真实内容和 DPI 验证；它们不是来源产品测量值、平台标准或所有用户的最佳答案。重要操作不能靠很小的辅助字承载。
- 不把适合英文标题的全大写、宽字距和极细字重套给中文；不要手工插空格来对齐中文。
- 使用代表性样本：`示例研究项目`、`demo-model`、`2026-01-01 09:30`、长项目名、路径、公式、中英混合消息和连续代码。检查标点断行、标签压缩、按钮换行和截断后的访问方式。
- 在正常窗口、窄窗口、Windows 实际缩放下检查；截图缩放后好看不算原始显示合格。

## 5. 让视觉系统承受内容变化

定义一小组语义 token，不把每个像素都参数化：字体角色、间距节奏、基础/内容/浮层表面、文字层级、强调与状态、圆角和运动。明暗主题共享角色，不直接把浅色 HEX 机械反转。

- **颜色**：强调色用于选择、优先行动或品牌识别；错误/成功有独立语义且配文字或图标。避免为了让辅助界面退后而把文字降到难读。
- **表面**：相同层级用相同规则；重阴影用于真正悬浮的对象时更容易解释。玻璃、噪点、光晕都可用，但要说明它们的作用和所在层，不以效果数量验收。
- **图像**：让封面、头像和背景成为系统的一部分；提供适合用途的完整显示/裁切策略。文字可通过局部表面保持可读，不擅自把用户背景一律重度淡化。
- **动效**：区分状态提示、空间转换和纯装饰。发送立即给出本地反馈；思考、调用工具、等待批准、失败各自真实；尊重减少动态效果设置。不要让每个文字都闪烁来妨碍阅读。
- **控件**：选中项、焦点和主动作的表现贯穿列表、弹窗与设置。漂亮按钮不能代替清楚的命名和可发现的入口。

## 6. 先做代表页，再铺开

在授权实现视觉改造时，先做最能代表主要工作的高保真页面，使用长短混合的真实风格内容；加一个忙碌、错误或复杂状态验证其承受力。随后再扩展到本轮范围内的关联页面。不要先全局替换样式，再希望所有页面自动变好。

多人智能体应用的范围若是整体验收，考虑：项目选择、正常聊天、长消息与附件、智能体配置、工具/权限批准、任务及资料详情、空状态和失败恢复。只被授权改一个局部时，不借此改造所有页面。

“待开发功能”也需要对象、入口、主要内容和完成/退出路径；先给可审阅的交互方案，不擅自实现后台能力。

## 7. 两道验收门，不能互相替代

**功能门**：任务走得通、数据保留、状态真实、窗口和键盘可用、无阻塞问题。

**视觉门**：整体焦点明确，同类组件一致，中文排版舒适，真实内容不破坏构图；与选定参考相比的明显差距已解释或处理。视觉判断写出证据与取舍，不制造“审美 95 分”之类伪测量。

使用同尺寸、同缩放、同主题和相当内容量的前后截图。每轮记录一个最主要的视觉问题及对应修改，再看原始渲染确认改善；不要无限抛光或把试验性取舍包装为定论。测试全绿而用户指出的拥挤、廉价感或风格混乱仍在，就继续处理对应设计原因。

研究/评审任务交付来源、观察和建议；实现任务交付实际渲染与验证。更新 skill 本身不能宣称软件页面已经变好。
