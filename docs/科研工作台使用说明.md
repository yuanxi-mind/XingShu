# 星枢 · 科研工作台 0.4.14

打开桌面“星枢”，进入项目，点击聊天页右上角“科研工作台”。
每个项目独立保存 Agent、聊天、四盒、评测、实验包和服务器连接；只允许手动复用中转地址与密钥。

## 四项能力在哪里

| 入口 | 你能做什么 | 结果在哪里 |
| --- | --- | --- |
| 能力评测 | 同一组合成小题测试指定伙伴；看读文件、精确修改、核查、算指标和证据边界 | 项目内 `runs/research-evaluations/`，JSON与Markdown报告 |
| 证据追溯 | 查看原文—方案—实际代码—检查—实验—结论之间的关系；按伙伴权限检索记忆 | `runs/research/evidence-index.json`，原始凭据仍在四盒内 |
| 可复现实验 | 打包指定代码、配置、依赖和多个seed；手动上传或批准SSH提交；取回日志与指标 | `runs/experiment-bundles/` |
| 执行记录 | 暂停科研任务，重启后确认续跑，跳过有回执的工具 | `runs/research/checkpoints/`与执行时间线 |

## 从 baseline 到确认结果

1. **放资料。** 在“资料与版本”导入原始代码文件夹和论文。导入是复制；公共版本只读。
2. **想方案。** 点击“独立想方案”，选择伙伴、写清任务。各自在私人空间工作，方案分别私聊给你。
3. **开会和选人。** 在“方案与实验”只公开你选中的方案；采纳后指定修改者和另一位检查者。下一轮可以换人。
4. **改与查。** 修改者只改私人工作副本；检查者逐条核对实施清单与实际文件。核查通过还不能当作提分证据。
5. **跑实验。** 在“可复现实验”分别选当前公共版、已核查候选方案，填写相同运行条件，各生成一个包。
6. **回收与确认。** 导入服务器结果，检查代码、划分、日志和数值，再点“人工确认包内实验结果”。确认之前不会进入事实盒。
7. **比较与发布。** 选择对照包和候选包，核对多seed均值差；再到“方案与实验”指定本轮发布者。旧公共版本保留。

失败实验也记录，避免重复尝试。人工确认是你认可这次观察，不代表结论已被独立复跑或普遍成立。

## 让多位伙伴补齐同一个对照

1. 打开「科研工作台 → 可复现实验 → 实验推导记忆 → 新建对照卡」。选定公共对照包、候选包和要比较的随机种子。选包是为了锁定代码和运行条件；可以将种子分几个实验包记录。
2. 导入并人工确认实验结果。回到「登记或指派回执」，可以直接登记，也可以分派给不同 Agent。被指派的伙伴需要在你与它的私聊中，按你的指示调用工具提交回执。
3. 点「重新核验记忆」。每个种子都有对应两边的指标且没有冲突时，才显示差值和来源。卡片与回执默认只有你能看；群聊只能用明确公开过的卡片与回执，可能比你看到的结果少。
4. 更正时，在「已登记回执」撤回旧的来源，保留原文件，再核验并登记更正后的实验包。缺少证据的卡会隐藏差值，已有的聊天文本不会回写。这里撤回的是推导来源，不会删除原有的实验记录。

## 先测伙伴，再安排分工

“离线流程自检”使用固定正确答案和故障答案，检查评分流程，**不联网、不评任何真实模型**。
“真实模型评测”才会调用你配置的中转和模型；需要核对对象、题目、重复次数、请求数、输出量和时长，并明确批准。

每位伙伴可选不同连接、模型和推理强度。报告保留本次身份快照、工具记录和逐项断言。
题库包含6类合成基础题，不认证科研新颖性、论文写作质量，也不据此自动分配永久角色。
你可以填写人民币/百万token单价。缺少单价或中转usage时显示“未知”，不当作0元。
请求数与时长限制不是供应商账单硬上限；取消也不能保证中转立即停止计费。

## 怎么填写实验参数

- **训练入口：** 代码中的相对路径，例如 `train.py`。
- **依赖文件：** 例如 `requirements.txt`；记录并核对文件哈希，不会自动安装依赖。
- **数据集／划分：** 写实际使用的数据。建议提供代码中的划分清单，例如 `splits/test.txt`，便于核对其哈希。
- **训练参数：** JSON数组，例如 `["--config","configs/cd.yaml","--data","/datasets"]`，不会拼接shell命令。
- **镜像digest：** 服务器已安装的固定镜像，例如 `你的镜像@sha256:64位校验值`。不能用会漂移的 `latest`。
- **seed：** 1–5个不重复整数。多seed对照至少2个，默认1、2、3。
- **指标：** 训练结束须把JSON数字写到指定路径，例如工作目录的 `metrics.json` 内容为 `{"F1":90.5}`。单位可选百分数、比例或其他数值。
- **资源：** 每seed的训练时限、CPU、内存和GPU编号。代码与每个seed工作目录隔离，数据集只读映射为 `/datasets`。

生成包后点击“定位实验压缩包”。上传并解压后，按包内 `README.txt` 操作。
可先运行 `python3 run_experiment.py --manifest-sha256 <包内校验值> --check-only`，只核对清单，不训练。
运行后把整个 `results` 文件夹带回，选择其中的 `bundle-results.json` 导入，不能只复制一个JSON文件。
单个训练日志回收最多保留末尾1MiB，并记录原始日志体积；完整日志仍应由你在服务器上另行管理。

## 可选：软件直接提交到你的服务器

服务器需为Linux，预装Python3、Docker及指定digest镜像，使用非root SSH用户。
在“服务器连接”填写主机、端口、用户、工作根目录、数据集目录；选择D盘SSH私钥。
主机SHA256指纹需要向服务器管理员核实。先“保存服务器连接”，再“核验指纹并测试连接”。

提交时软件显示seed数、时限和资源，需要你勾选并批准。Agent不能自己批准或读取私钥。
断线后先查状态，**不会自动重提训练**；同一包使用唯一目录和运行锁。状态不确定时保留“待核对”，不冒充成功。
只停止本包对应的训练容器。服务器配置变化后，旧包拒绝误操作另一台服务器。

容器采用禁网、只读根目录、非root、权限与CPU/内存/进程数限制；每个seed在独立副本里执行。
镜像、依赖文件与数据划分的哈希核对，不能证明数据无泄漏或指标真实，也不能保证跨硬件逐位一致。
本功能不配置服务器磁盘配额；请使用你有权限管理、空间充足的科研服务器。

## 暂停和续跑

在“执行记录”点击“暂停并保存断点”。关闭软件后，原任务、模型上下文、工具回执和代码副本保留。
再次打开项目，选择该记录的“从断点继续”，确认后才请求中转。

模型、中转地址、系统提示、公共版本、实施授权或工作副本变化，会阻止过期断点恢复。
有完整回执的工具不会重做；能核对修改已落盘的情况会恢复回执。
无法确认的副作用会停下，要求核对，不能假设任意崩溃窗口都能自动恢复。
中断的模型请求可能已经计费；重试该请求可能再次收费。

能力评测重启后只保留中断报告，不自动重放收费评测；它与科研任务的断点续跑分开处理。

## 数据与验收边界

软件数据、项目资料、日志、缓存与本地测试文件都位于D盘。Windows自身的系统写入不在应用控制范围内。
此版使用隔离模拟中转、模拟结果和Python容器调用夹具验收；不擅自花费你的API余额，也不启动真实服务器训练。
真实模型的科研表现与实际服务器环境，需要你配置并批准后实测。系统降低错误与越权风险，不能承诺零幻觉或保证提分。
